# Security policy

## Supported release

The project is preparing its v0.1.0 public preview. Until a release is
published, report findings against the current repository state. After releases
exist, identify the affected tag in the private report.

## Reporting a vulnerability

Use GitHub's **Private vulnerability reporting** entry on this repository's
Security tab. Do not open a public issue, pull request, branch, or discussion for
an unpatched vulnerability, exposed credential, or exploitable defect.

Include the affected component or file, impact, reproduction details, and any
known workaround without pasting live secrets. If a credential is exposed,
rotate or revoke it at its source before history cleanup is considered.

The maintainers will assess reports through GitHub's private security workflow.
This policy does not promise a response or remediation time. Availability and
timing depend on the finding and maintainer capacity.
